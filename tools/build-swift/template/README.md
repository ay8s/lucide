# {{MODULE}}

[Lucide](https://lucide.dev) as a Swift package: the icon font plus a generated,
compile-time-checked constant for every icon name.

- **{{ICON_COUNT}} icons**, {{ALIAS_COUNT}} alternative names, from
  `lucide-static@{{LUCIDE_VERSION}}`.
- Names are checked by the compiler. Referencing an icon that Lucide renamed or
  removed is a build-time warning, not an empty box at runtime.
- Draw icons as text (vector, tintable, Dynamic Type) or as an image, inline in
  a sentence, in a `Label`, or through UIKit and AppKit.

> This package is generated by `tools/build-swift` in the Lucide fork. Don't edit
> the sources by hand, regenerate them instead — see [Regenerating](#regenerating).

## Installation

```swift
.package(url: "{{PACKAGE_URL}}", from: "{{LUCIDE_VERSION}}")
```

```swift
.target(name: "YourApp", dependencies: ["{{MODULE}}"])
```

The font registers itself with Core Text the first time you use it, so there is
nothing to add to `Info.plist` and nothing to call at launch.

## Versioning

The package version is the `lucide-static` release its font came from, so
`{{LUCIDE_VERSION}}` here means Lucide `{{LUCIDE_VERSION}}` — there is no second
version to reconcile. The Swift API is stable across those releases: icons that
Lucide removes or renames arrive as deprecations rather than breaking changes,
which is the point of the generated constants.

```swift
LucideFont.lucideVersion  // "{{LUCIDE_VERSION}}"
LucideFont.iconCount      // {{ICON_COUNT}}
```

The package root also holds a `.lucide-version` file, so a release script can
read the tag straight out of the checkout. If the package itself needs a fix
before the next Lucide release, bump the patch and let the following
font-matching tag skip that patch number.

## Text or image?

Every icon can be drawn two ways, and the text one is almost always what you
want:

|                    | `LucideIconView` / `Text`             | `Image(_:pointSize:)`                     |
| ------------------ | --------------------------------------- | ----------------------------------------- |
| What it is         | a glyph in the Lucide font              | the glyph rasterised into a bitmap        |
| Scaling            | vector at any size, follows Dynamic Type | fixed at `pointSize`                      |
| Colour             | `foregroundStyle`                        | `foregroundStyle`, it is a template image |
| Use it for         | anything you lay out yourself            | APIs that insist on an `Image` or `UIImage` |

## SwiftUI

### As a view

```swift
import {{MODULE}}
import SwiftUI

LucideIconView(.circleCheck, size: 20)
    .foregroundStyle(.green)
```

It scales with Dynamic Type relative to `.body` by default. Pass a different
text style to match the text beside it, or `nil` to pin the size:

```swift
LucideIconView(.trash2, size: 17, relativeTo: .headline)
LucideIconView(.trash2, size: 17, relativeTo: nil)      // fixed
```

Icons are hidden from assistive technologies unless you give them a label:

```swift
LucideIconView(.trash2, size: 17, label: Text("Delete"))
```

### Inline in text

Interpolate an icon straight into a string, and it renders between the words
with the Lucide font applied to just that run:

```swift
Text("Saved to \(LucideIcon.folder) Drafts, sends \(LucideIcon.clock) 09:00")
Text("Saved to \(LucideIcon.folder, size: 13) Drafts")           // match the surrounding size
Text("Fixed \(LucideIcon.folder, size: 13, relativeTo: nil)")    // no Dynamic Type scaling
```

Or concatenate text runs, which gives you per-run styling:

```swift
Text(LucideIcon.circleCheck, size: 15).foregroundStyle(.green)
    + Text(" Published to 3 channels")
```

`Text(LucideIcon.house)` on its own leaves the font to you, for when a whole
block of text is in the icon font:

```swift
Text(LucideIcon.house)
    .font(.lucide(size: 17))
```

### Labels and buttons

```swift
Button(role: .destructive) { delete() } label: {
    Label("Delete", lucide: .trash2)
}

Menu {
    Button { schedule() } label: { Label("Schedule", lucide: .calendarPlus, size: 15) }
} label: {
    LucideIconView(.ellipsis, size: 18)
}
```

### As an image

For the APIs that take an `Image` rather than a view:

```swift
Image(.house, pointSize: 20)
    .foregroundStyle(.purple)

ShareLink(item: url) { Label { Text("Share") } icon: { Image(.share2, pointSize: 16) } }
```

### The font itself

```swift
Font.lucide(size: 17)                        // fixed size
Font.lucide(size: 17, relativeTo: .body)     // scales with Dynamic Type
```

## UIKit

```swift
// The font, for anything that draws text.
label.font = .lucide(ofSize: 17)
label.text = LucideIcon.house.glyph

// An attributed run, which takes the label's own colour when you don't pass one.
label.attributedText = LucideIcon.house.attributedString(pointSize: 17)

// Inline in a sentence.
let line = NSMutableAttributedString(attributedString: LucideIcon.clock.attributedString(pointSize: 13))
line.append(NSAttributedString(string: " Sends at 09:00"))
label.attributedText = line

// An image, for the APIs that only take images. Without a colour you get a
// template image, so it follows the tint colour.
tabBarItem.image = LucideIcon.house.image(pointSize: 22)
button.setImage(LucideIcon.plus.image(pointSize: 17, color: .white), for: .normal)
```

## AppKit

The same three, with AppKit types: `NSFont.lucide(ofSize:)`,
`attributedString(pointSize:color:)` and `image(pointSize:color:)`. An image
without a colour comes back with `isTemplate` set, so it follows the surrounding
style.

## Names that only exist at runtime

Icon names coming from an API or from stored data can be looked up by name.
Alternative names resolve to their canonical icon, removed names resolve to
`nil`.

```swift
LucideIcon(name: "circle-check")              // LucideIcon.circleCheck
LucideIcon(name: "alarm-check")               // LucideIcon.alarmClockCheck, an alternative name
LucideIcon(name: "twitter")                   // nil, removed from Lucide
LucideIcon.canonicalName(for: "alarm-check")  // "alarm-clock-check"
LucideIcon.allIcons                           // every icon, ordered by name
LucideFont.hasGlyph(for: icon)                // would this render?
```

`LucideIcon` is `Codable` and encodes as its canonical name, so persisted icons
keep working across font updates:

```swift
try JSONEncoder().encode(LucideIcon.house)  // "house"
```

## How names map

Kebab-case Lucide names become lowerCamelCase Swift names, the same conversion
the JavaScript packages use for their component names:

| Lucide            | Swift               | React              |
| ----------------- | ------------------- | ------------------ |
| `circle-check`    | `.circleCheck`      | `<CircleCheck />`  |
| `arrow-up-right`  | `.arrowUpRight`     | `<ArrowUpRight />` |
| `a-arrow-down`    | `.aArrowDown`       | `<AArrowDown />`   |

A handful of icon names are Swift keywords (`import`, `repeat`, `subscript`).
They are declared with backticks, and `LucideIcon.import` works as written.

## What happens when Lucide updates

Code points are allocated once per icon and never reused, so updating the font
never moves an existing icon to a different glyph. What changes is the set of
names:

- **Added icons** show up as new constants.
- **Renamed icons** keep the old name as a deprecated alternative that resolves
  to the new icon, so the compiler points at the replacement.
- **Removed icons** ({{REMOVED_COUNT}} today, mostly the brand icons dropped in
  Lucide 1.0) keep their constant, marked deprecated: the name still compiles
  with a warning telling you it renders as blank space.

That is the difference from writing the character out by hand: a name that
changes upstream surfaces at build time, at the exact call sites that need
changing.

The tests check that every generated constant still has a glyph in the bundled
font, that the constants and the bundled lookup table agree, and that every
alternative name resolves, so a bad font update fails `swift test` rather than
shipping.

## Regenerating

From a checkout of the Lucide fork that holds `tools/build-swift`:

```sh
pnpm build:swift --module={{MODULE}} --repo-url={{PACKAGE_URL}} --out=../{{MODULE}}
```

It reports what changed (`added since the last run`, `gone since the last run`),
and `--check` instead of writing tells you whether this package is up to date.
Then test and release, tagging with the Lucide version the generator wrote:

```sh
swift test
git commit -am "Lucide $(cat .lucide-version)"
git tag -a "$(cat .lucide-version)" -m "Lucide $(cat .lucide-version)"
git push && git push origin "$(cat .lucide-version)"
```
